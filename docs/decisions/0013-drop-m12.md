# 0013 — Drop M12 (Leaving agents running)

- Date: 2026-10-07
- Status: accepted
- Milestone: M12

## Context

The human decided not to build M12 (SPEC §20D): webhook notifications, rate-limit
auto-continue, task chains with `tasks.max_running`, and the agent-driven CLI (`mk session
read/spawn --prompt`, `mk --skill`, `created_by`). None of it was implemented. M9 had already
added the `notify.webhook` and `tasks.max_running` settings keys with no consumer.

## Options

1. Drop M12 and renumber M13 → M12 — tidy numbering, but churns every `M13`/`§20E` reference
   (ADR 0010, BUILD_LOOP gate, PROGRESS).
2. Drop M12 and keep the numbers — a gap in the sequence, no other reference changes.

## Decision

Option 2. M12 is removed from §18, §20D shrinks to a "dropped" note, and its settings keys,
profile keys (`rate_limit_patterns`, `continue_text`), migration `0009_agent_runs.sql`, fake-agent
`rate_limit` step and protocol additions are gone. M13 follows M11; its migration becomes
`0009_worktrees.sql`. Numbers M12 and §20D are not reused.

## Consequences

- SPEC §1, §5 note, §18, §20, §20.0, §20D, §20E, §20F updated.
- `mkrew_core::settings` loses `notify.webhook` and `[tasks]`; a `settings.toml` that still has
  them now fails to parse (unknown keys are errors) — remove those lines.
- After M11 the build loop plans M13; the loop still ends after M13.
