# macOS app integration (Plan C of 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Mkrew behave like a Mac app around its windows and the Dock: a menu bar with working Cmd+Q / Cmd+H / Cmd+M, a window that remembers its place, traffic lights that stay centered, a Dock badge and bounce, the user's shell `PATH` when started from Finder, and a signed, notarized, iconned `Mkrew.app`.

**Architecture:** Pure, unit-tested decisions live in the lib crate and take `crate::keymap::Os` (Plan A) or an explicit flag, so macOS behavior is tested on the Windows dev machine: `app_menu` (menus and menu-only keys), `window_place::Placement` / `restored`, `theme::traffic_light_pos` / `title_bar_inset`, `desktop::badge_label` / `can_hide_on_close`, `mk_install`, `zed::mac_cli_candidates`, and `mkrew_core::login_path` (parse, merge, probe).
The only macOS-only code is a few safe `objc2` calls in `desktop/dock.rs` and one `Window::set_traffic_light_position` call; both are compiled only by the macOS CI job (Plan A Task 1).
The process environment is never changed (`std::env::set_var` is `unsafe`, and the workspace denies `unsafe_code`): `login_path::path()` hands the merged `PATH` to the callers that look programs up or start agents.

**Tech Stack:** Rust 2024, gpui-pre 0.3.7 (`App::set_menus`, `on_action`, `on_app_quit`, `Application::on_reopen`, `Window::request_attention`, `Window::set_traffic_light_position`), `objc2-app-kit` 0.3.2 and `objc2-foundation` 0.3.2 (already in `Cargo.lock` through gpui-pre-macos), bash with `sips`, `iconutil`, `codesign`, `xcrun notarytool`, GitHub Actions.

**Spec:** `docs/SPEC.md` §10 (title bar), §20J (tray, badge, close), §20K (in-app update), §8 "Command lookup", the "Open in Zed" bullet, §4 repo layout, plus the audit `agent://MacWindowChrome` (read 2026-11-21).
This plan writes `docs/decisions/0100-macos-app-integration.md` and the new SPEC §20L in Task 1, before any behavior, so every later task cites them.
Later tasks touch SPEC only for a sentence their code contradicts.

````markdown
# 0100 - macOS app integration

- Date: 2026-11-22
- Status: accepted (SPEC §4, §8, §10, §20J, §20K, new §20L; extends ADR 0064 and ADR 0071; Plans A and B of the same audit are ADR 0098 and ADR 0099)
- Milestone: none (user request 2026-11-22, macOS audit)

## Context

The audit of the macOS build (`MacWindowChrome`, 2026-11-21) found that the app has no menu bar, quits from the Dock without asking, does not get the user's `PATH` when opened from Finder, forgets its window place, bounces and badges nothing, and ships without an icon, a Developer ID signature or notarization.
Facts checked in `gpui-pre 0.3.7`:

- `cx.set_menus` exists and is never called; its menu items dispatch GPUI actions, so the keymap's own `Run(Command)` actions can be reused.
- `cx.on_app_quit` cannot cancel a quit and gets 200 ms; macOS reaches it from `applicationWillTerminate`, so Dock Quit and log-out cannot be vetoed from Rust without adding `applicationShouldTerminate:` to gpui's private delegate (an `unsafe` runtime call the workspace denies).
- `cx.on_reopen`, `cx.hide`, `Window::request_attention` and `Window::set_traffic_light_position` exist; there is no Dock badge call.
- `objc2-app-kit` 0.3.2 and `objc2-foundation` 0.3.2 are already in `Cargo.lock` (gpui-pre-macos depends on them) and offer safe wrappers for `NSApp.dockTile.badgeLabel` and the standard About panel.
- A Finder or Dock launch gets launchd's `PATH=/usr/bin:/bin:/usr/sbin:/sbin`.

## Decision

1. **Menu bar** through `cx.set_menus`: Mkrew (About, Settings, Check for Updates, Services, Hide, Hide Others, Show All, Quit), Edit (Copy, Paste), View (Enter Full Screen), Window (Minimize, Zoom).
   Settings, Copy, Paste and Full Screen reuse `Run(Command)`, so the menu shows the user's keys.
   New menu-only actions: `Quit` (cmd-q), `Hide` (cmd-h), `HideOthers` (alt-cmd-h), `ShowAll`, `Minimize` (cmd-m), `Zoom`, `About`, `CheckForUpdates`.
   The menu-only keys are bound before the keymap's, so a key the user binds wins.
   Edit has Copy and Paste only: the Files editor and the text fields take key events, not actions, so a menu click cannot reach them (the keys work).
2. **Quit.** Cmd+Q and the Quit item run `quit_ui` (unsaved Files changes asked first).
   Dock Quit and log-out cannot be vetoed (above): `on_app_quit` saves the window places and asks the machine windows to quit; unsaved Files changes are lost on those two paths.
   This is a known gap, listed in SPEC §20L; closing it needs gpui to expose `applicationShouldTerminate:`.
3. **Closing the main window: keep the app alive.**
   Options: (a) keep quit-on-close and document it; (b) really close the window and rebuild it in `on_reopen`; (c) hide the app (`cx.hide()`) and bring it back from the Dock.
   Chosen: (c), on the existing `[ui] close_to_tray` setting (default on; machine windows excluded as today).
   Why: an agent that needs input is only noticed while the process lives, and the Dock badge and bounce need it; Windows already hides to the tray by default for the same reason, so (c) is the Mac form of the same rule; (c) keeps all state (unsaved Files edits, scrollback, detached windows) while (b) would drop `Shell`, which the detached windows hold, and rebuilding it is a large refactor with no way to test it on the dev machine; the daemon keeps the agents running either way, so (a) would only lose the attention signals.
   Cmd+Q quits; `close_to_tray = false` makes the red button quit.
   `on_reopen` (Dock click with no visible window) shows the main window.
4. **Window place.** The main window's restore rect, maximized and full screen state are saved in `<data>/main-window.json` (a machine window: `main-window-<key>.json`) and restored on every OS; saved places on a gone monitor move to the primary display; the size is at least the minimum.
   A detached window now keeps full screen too (`fullscreen` in `windows.json`, absent = false).
   New and restored windows are fitted to `visible_bounds()` so they never open under the menu bar or Dock.
5. **Traffic lights** are placed with `Window::set_traffic_light_position` from the title bar's height at the current `[ui] font_size` (y = (bar - 14) / 2), only when it changes; the 72 px left padding is dropped in full screen.
6. **Dock.** Badge: `NSApp.dockTile.badgeLabel` through safe `objc2` calls, the same count as the Windows overlay, `99+` from 100.
   Bounce: `Window::request_attention` (one bounce) where Windows flashes the taskbar, under the same `[notify] flash_taskbar` setting.
7. **PATH.** The first lookup asks `$SHELL -l -i -c` (5 s limit, `/bin/zsh` if `$SHELL` is unset) for its `PATH` between markers and merges it before the process's own; the result is cached in a `OnceLock` in `mkrew_core::login_path` and warmed on a thread at start of the UI and of the daemon.
   `lookup::find` and the PTY command use it; the process environment is not changed.
   The default shell starts with `-l` on macOS (Terminal.app does too).
8. **Zed on a Mac** is also looked for in `/usr/local/bin`, `/opt/homebrew/bin`, `~/.local/bin` and inside `Zed.app`; with only the app installed, `open -a <Zed.app> <path>` opens the file (without a line).
9. **`mk` command.** Palette "Global: Install mk command" (only in a `Mkrew.app` that is not translocated) links `/usr/local/bin/mk`, else `~/.local/bin/mk`, to the bundle's `mk`.
   A real file named `mk` is never replaced.
10. **Packaging.** `Mkrew.icns` from `packaging/macos/mkrew-1024.png` (the lanes tile, `icon/mkrew-1-lanes/tile-dark.svg`) with `sips` and `iconutil`; `CFBundleIconFile`; Developer ID signing with the hardened runtime and the audio-input entitlement, `notarytool` and `stapler`, all gated on repository secrets, else the ad-hoc signature as before.
    The bundle's `agents/` copy leaves out `cmd.toml`, `powershell.toml` and `git-bash.toml`.
11. **Not built.**
    Single instance on macOS: LaunchServices already reuses a running bundle for Finder, Dock and `open`; a second launch of the binary from a terminal shares the daemon and is harmless (as on Linux); the Windows-only parts (toast links, launcher raise) have no macOS counterpart.
    A Dock menu (`set_dock_menu`): not requested.
    `mkrew --machine` children keep their own Dock icon: each machine window is its own process (ADR 0089), and making it an accessory app would remove its menu bar and Cmd+Tab entry.
    Windows-only profiles stay compiled into the daemon and seeded into the config folder (the New menu already hides profiles whose program is not installed); only the bundle's reference copy is filtered.

## Consequences

- SPEC: §20L added; §4, §8, §10, §20J, §20K, the Zed bullet and two settings comments amended.

- The repository needs six secrets to sign and notarize (listed in Task 10); without them releases stay ad-hoc signed.
- Risk: several behaviors cannot be run on the dev machine; each has a line in `docs/HUMAN_CHECKS.md` "To verify".
````

```markdown
### §20L macOS app integration (outside the milestones, ADR 0100)

What a Mac user expects of an app around its windows and the Dock.
macOS only unless a line says "every OS".

1. **Menu bar.**
   `Mkrew`: About Mkrew (the standard panel, from the bundle's Info.plist), Settings…, Check for Updates… (not in a machine window), Services, Hide Mkrew, Hide Others, Show All, Quit Mkrew.
   `Edit`: Copy, Paste.
   `View`: Enter Full Screen.
   `Window`: Minimize, Zoom.
   Settings, Copy, Paste and Enter Full Screen are the keymap's own commands (`open_settings`, `copy`, `paste`, `toggle_full_screen`), so the menu shows the user's keys.
   Quit (Cmd+Q), Hide (Cmd+H), Hide Others (Option+Cmd+H) and Minimize (Cmd+M) are menu-only keys; a key bound in `keymap.toml` wins.
   Copy and Paste act in terminals only: the Files editor and text fields take key events, not menu actions (their keys work).
2. **Quit.**
   Cmd+Q and Quit Mkrew run "Quit UI" (§20J): unsaved Files changes and prompt drafts are asked first, the machine windows are asked to quit, the daemon and the agents keep running.
   Dock → Quit and log-out end Mkrew without a question (gpui cannot veto them): the window places are saved, the machine windows are asked to quit, unsaved Files changes are lost.
3. **Close.**
   While `[ui] close_to_tray` is on (default), the red button hides the app like Cmd+H; a click on the Dock icon, or Cmd+Tab, shows it again with its state (panes, unsaved Files changes, detached windows).
   The Dock badge and bounce keep working while hidden.
   `false`, or a machine window: the red button asks about unsaved changes and quits.
4. **Window place (every OS).**
   The main window's restore rect, maximized and full screen state are kept in `<data>/main-window.json` (a machine window: `main-window-<key>.json`) and restored at the next start; a place on a monitor that is gone moves to the primary display; the size is never below 1100 x 560; a missing or broken file opens the window centered at 1200 x 760 as before.
   A detached window keeps full screen too (`fullscreen` in `windows.json`; absent = false).
   New and restored windows are kept inside a display's visible area (menu bar and Dock excluded).
5. **Traffic lights.**
   Centered on the title bar at any `[ui] font_size` (y = (bar height - 14) / 2, set when the size changes); no left gap for them in full screen.
6. **Dock.**
   The badge shows the Needs-you count (§20J), `99+` from 100, cleared at 0.
   When a session enters `needs_input` while no Mkrew window is active and `[notify] flash_taskbar` is on, the icon bounces once.
7. **PATH.**
   The first program lookup asks the login shell (`$SHELL -l -i -c`, `/bin/zsh` if unset, 5 s limit) for its `PATH` and puts it before the process's own; agents and shells started by the daemon get it, and "Open in Zed" finds `zed` with it.
   The default shell is started as a login shell.
   If the shell fails or times out, the process's own `PATH` is used.
8. **`mk` command.**
   Palette "Global: Install mk command" (listed only in `Mkrew.app`, not in a translocated copy) links `/usr/local/bin/mk`, else `~/.local/bin/mk`, to the bundle's `mk`; a toast names the link and says when its folder is not on `PATH`.
   A real file named `mk` is never replaced.
9. **Packaging.**
   `Mkrew.app` has an icon (`Mkrew.icns`) and leaves the Windows-only profiles out of its `agents/` copy.
   The release job signs with Developer ID (hardened runtime, microphone entitlement), notarizes and staples when the repository has the secrets `MACOS_CERTIFICATE_P12`, `MACOS_CERTIFICATE_PASSWORD`, `MACOS_SIGN_IDENTITY`, `APPLE_ID`, `APPLE_APP_PASSWORD` and `APPLE_TEAM_ID`; otherwise it signs ad-hoc, and Gatekeeper blocks the first open (README: Open Anyway on macOS 15 and later, or `xattr -dr com.apple.quarantine`).
10. **Not done.**
    Single instance (LaunchServices reuses a running bundle; a terminal launch shares the daemon), a Dock menu, a window list in the Window menu, raising a running machine window from the launcher, and a veto of Dock Quit / log-out.
    Each `mkrew --machine` window is its own process with its own Dock icon (ADR 0089).
```

```rust
/// How a window sits on its screen.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum Placement {
    #[default]
    Windowed,
    Maximized,
    /// The OS full screen (macOS: its own Space).
    Fullscreen,
}

impl Placement {
    /// The saved flags; a file with both set means full screen.
    pub fn from_flags(maximized: bool, fullscreen: bool) -> Self {
        if fullscreen {
            Self::Fullscreen
        } else if maximized {
            Self::Maximized
        } else {
            Self::Windowed
        }
    }

    /// `(maximized, fullscreen)`, as `windows.json` and `main-window.json` keep them.
    pub fn flags(self) -> (bool, bool) {
        (self == Self::Maximized, self == Self::Fullscreen)
    }

    /// `Window::window_bounds()` as the placement and the rect the window restores to.
    pub fn of(bounds: WindowBounds) -> (Self, Bounds<Pixels>) {
        match bounds {
            WindowBounds::Windowed(rect) => (Self::Windowed, rect),
            WindowBounds::Maximized(rect) => (Self::Maximized, rect),
            WindowBounds::Fullscreen(rect) => (Self::Fullscreen, rect),
        }
    }

    /// The gpui bounds that open a window in this placement, restoring to `restore`.
    pub fn window_bounds(self, restore: Bounds<Pixels>) -> WindowBounds {
        match self {
            Self::Windowed => WindowBounds::Windowed(restore),
            Self::Maximized => WindowBounds::Maximized(restore),
            Self::Fullscreen => WindowBounds::Fullscreen(restore),
        }
    }
}

/// Where a saved window opens: `saved` grown to at least `min` and moved to the primary display
/// when no display shows it any more ([`fit_on_displays`]), in `placement`.
pub fn restored(
    saved: Bounds<Pixels>,
    placement: Placement,
    min: Size<Pixels>,
    displays: &[Bounds<Pixels>],
    primary: Option<Bounds<Pixels>>,
) -> WindowBounds {
    let grown = Bounds::new(
        saved.origin,
        size(
            saved.size.width.max(min.width),
            saved.size.height.max(min.height),
        ),
    );
    placement.window_bounds(fit_on_displays(grown, displays, primary))
}

/// A saved rect as screen bounds.
pub fn saved_rect(saved: &SavedBounds) -> Bounds<Pixels> {
    Bounds::new(
        point(px(saved.x), px(saved.y)),
        size(px(saved.width), px(saved.height)),
    )
}

/// Screen bounds as a saved rect.
pub fn to_saved(bounds: Bounds<Pixels>) -> SavedBounds {
    SavedBounds {
        x: f32::from(bounds.origin.x),
        y: f32::from(bounds.origin.y),
        width: f32::from(bounds.size.width),
        height: f32::from(bounds.size.height),
    }
}
```

```rust
pub fn save(path: &Path, windows: &[SavedWindow]) -> std::io::Result<()> {
    write_atomic(path, &to_json(windows))

fn write_atomic(path: &Path, text: &str) -> std::io::Result<()> {
    if let Some(dir) = path.parent() {
        std::fs::create_dir_all(dir)?;
    }
    let temp = path.with_extension("json.tmp");
    let result = std::fs::write(&temp, text).and_then(|()| std::fs::rename(&temp, path));
    if result.is_err() {
        let _ = std::fs::remove_file(&temp);
    }
    result
}

/// How the main window was left (`main-window.json`): the rect it restores to, and whether it
/// was maximized or in full screen.
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct SavedFrame {
    pub bounds: SavedBounds,
    #[serde(default)]
    pub maximized: bool,
    #[serde(default)]
    pub fullscreen: bool,
}

impl SavedFrame {
    /// `None` for text that is not a frame or holds a size no window can have: the window then
    /// opens centered as before, never in a broken place.
    pub fn parse(text: &str) -> Option<Self> {
        let frame: Self = serde_json::from_str(text).ok()?;
        let b = &frame.bounds;
        let finite = [b.x, b.y, b.width, b.height].iter().all(|v| v.is_finite());
        (finite && b.width >= 1.0 && b.height >= 1.0).then_some(frame)
    }
}

}
```

```rust
//! The login shell's `PATH` for an app started from Finder or the Dock (macOS, SPEC §20L,
//! ADR 0100). launchd gives such an app `/usr/bin:/bin:/usr/sbin:/sbin`, so `claude`, `codex`
//! and `zed` in `/opt/homebrew/bin` or `~/.local/bin` are not found. A terminal's `PATH` is
//! built by the login shell's `.zprofile` and `.zshrc`; asking that shell once gives the same
//! list.
//!
//! The process environment is never changed (`std::env::set_var` is `unsafe`): [`path`] hands
//! the merged list to the callers that look programs up ([`crate::lookup`]) or start agents.

use std::ffi::{OsStr, OsString};
use std::io::Read;
use std::path::{Path, PathBuf};
use std::process::{Command, Stdio};
use std::sync::OnceLock;
use std::time::Duration;

const BEGIN: &str = "__MKREW_PATH_BEGIN__";
const END: &str = "__MKREW_PATH_END__";
/// Prints `$PATH` between the markers, so a banner or `motd` of the shell's rc files around it
/// is ignored. `printf` and `"$PATH"` work in zsh, bash and fish.
const SCRIPT: &str = "printf '%s%s%s' __MKREW_PATH_BEGIN__ \"$PATH\" __MKREW_PATH_END__";
/// Longest wait for the shell: a `.zshrc` with version managers takes 1 to 2 s.
const TIMEOUT: Duration = Duration::from_secs(5);

/// The `PATH` to look programs up on and to give agents: on macOS the login shell's list in
/// front of this process's own; `None` elsewhere (the process's own is right) or when the
/// shell gave no answer in time. The first call waits for the shell; [`warm`] makes that happen
/// on a thread at start.
pub fn path() -> Option<&'static OsStr> {
    static PATH: OnceLock<Option<OsString>> = OnceLock::new();
    PATH.get_or_init(|| {
        if !cfg!(target_os = "macos") {
            return None;
        }
        let shell = std::env::var_os("SHELL");
        let current = std::env::var_os("PATH");
        probe(shell.as_deref(), current.as_deref(), |command| {
            run(command, TIMEOUT)
        })
    })
    .as_deref()
}

/// Starts [`path`] on its own thread so the first lookup does not wait for the shell.
pub fn warm() {
    if cfg!(target_os = "macos") {
        let _ = std::thread::Builder::new()
            .name("mkrew-login-path".into())
            .spawn(|| {
                let _ = path();
            });
    }
}

/// Asks `shell` (zsh when unset: the macOS default since Catalina) through `run` and merges
/// its answer in front of `current`.
fn probe(
    shell: Option<&OsStr>,
    current: Option<&OsStr>,
    run: impl FnOnce(Command) -> Option<String>,
) -> Option<OsString> {
    let shell = shell
        .filter(|shell| !shell.is_empty())
        .unwrap_or(OsStr::new("/bin/zsh"));
    let stdout = run(shell_command(Path::new(shell)))?;
    Some(merge(parse(&stdout)?, current))
}

/// `shell -l -i -c <script>`: login and interactive, so both `.zprofile` and `.zshrc` run (VS
/// Code and Zed do the same). The variables keep a framework such as oh-my-zsh from asking
/// questions in a shell nobody sees.
fn shell_command(shell: &Path) -> Command {
    let mut command = Command::new(shell);
    command
        .args(["-l", "-i", "-c", SCRIPT])
        .env("MKREW_RESOLVING_ENVIRONMENT", "1")
        .env("DISABLE_AUTO_UPDATE", "true");
    command
}

/// The text between the markers; `None` for no markers, an unfinished answer or an empty `PATH`.
fn parse(stdout: &str) -> Option<&str> {
    let start = stdout.find(BEGIN)? + BEGIN.len();
    let len = stdout[start..].find(END)?;
    let path = stdout[start..start + len].trim();
    (!path.is_empty()).then_some(path)
}

/// `login` first, then the entries of `current` that it lacks.
fn merge(login: &str, current: Option<&OsStr>) -> OsString {
    let mut dirs: Vec<PathBuf> = std::env::split_paths(login).collect();
    for dir in current.map(std::env::split_paths).into_iter().flatten() {
        if !dirs.contains(&dir) {
            dirs.push(dir);
        }
    }
    std::env::join_paths(dirs).unwrap_or_else(|_| OsString::from(login))
}

/// Runs `command` with no input and returns what it printed up to the end marker; `None` when it
/// does not start or says nothing within `timeout`. The shell is killed either way (it may still
/// be running the rest of its rc files). ponytail: a background job an rc file started may keep
/// the pipe's reader thread alive; it holds nothing else.
fn run(mut command: Command, timeout: Duration) -> Option<String> {
    let mut child = command
        .stdin(Stdio::null())
        .stdout(Stdio::piped())
        .stderr(Stdio::null())
        .spawn()
        .ok()?;
    let mut out = child.stdout.take()?;
    let (sender, receiver) = std::sync::mpsc::channel();
    std::thread::spawn(move || {
        let (mut seen, mut chunk) = (Vec::new(), [0u8; 4096]);
        while let Ok(read) = out.read(&mut chunk) {
            if read == 0 {
                break;
            }
            seen.extend_from_slice(&chunk[..read]);
            if String::from_utf8_lossy(&seen).contains(END) {
                break;
            }
        }
        let _ = sender.send(String::from_utf8_lossy(&seen).into_owned());
    });
    let text = receiver.recv_timeout(timeout).ok();
    let _ = child.kill();
    let _ = child.wait();
    text
}
```

```rust
/// `open -a <app> <path>`: the last resort, it cannot take a line.
pub fn open_app_command(app: &Path, path: &Path) -> Command {
    let mut command = Command::new("open");
    command
        .arg("-a")
        .arg(app)
        .arg(path)
        .stdin(Stdio::null())
        .stdout(Stdio::null())
        .stderr(Stdio::null());
    command
}

fn open_app(app: &Path, path: &Path) -> Result<(), ZedError> {
    let mut child = open_app_command(app, path)
        .spawn()
        .map_err(|source| ZedError::Spawn {
            program: "open".into(),
            source,
        })?;
    std::thread::spawn(move || child.wait());
    Ok(())
}
```

```rust
pub(crate) fn bind_all(keymap: &Keymap, cx: &mut App) {
    let local = cx.try_global::<LocalWindow>().is_none_or(|local| local.0);
    let bindings = keymap.key_bindings(cx.keyboard_mapper().as_ref());

/// Runs `f` on the main window's shell (nothing when it is gone).
fn with_main(
    cx: &mut App,
    f: impl FnOnce(&mut Shell, &mut Window, &mut Context<'_, Shell>),
) {
    let Some(main) = cx.try_global::<MainWindow>().map(|main| main.0) else {
        return;
    };
    let _ = main.update(cx, f);
}

/// Runs `f` on the window that is active now.
fn with_active(cx: &mut App, f: impl FnOnce(&mut Window)) {
    if let Some(active) = cx.active_window() {
        let _ = active.update(cx, |_, window, _| f(window));
    }
}

/// question.
```

```rust
//! "Global: Install mk command" (macOS app, SPEC §20L, ADR 0100): a symlink to the bundle's
//! `mk` in a folder on `PATH`, so Terminal finds `mk` (the `mk` of the app is the one that
//! speaks the app's daemon protocol).

use std::ffi::OsStr;
use std::io;
use std::path::{Path, PathBuf};

/// The folders tried in order: `/usr/local/bin` (on every Mac's default `PATH`; writable
/// without admin only where Homebrew made it so), then `~/.local/bin` (always writable; the
/// user adds it to `PATH`).
pub fn link_dirs(home: Option<&Path>) -> Vec<PathBuf> {
    let mut dirs = vec![PathBuf::from("/usr/local/bin")];
    dirs.extend(home.map(|home| home.join(".local").join("bin")));
    dirs
}

/// What an install made.
#[derive(Debug, PartialEq, Eq)]
pub struct Linked {
    /// The link, `<folder>/mk`.
    pub link: PathBuf,
    /// Its folder is on `PATH` already.
    pub on_path: bool,
}

/// Links `target` as `mk` in the first of `dirs` that takes it; `path` (the `PATH` string) says
/// whether that folder is searched. An error lists why each folder refused.
pub fn install(target: &Path, dirs: &[PathBuf], path: Option<&OsStr>) -> Result<Linked, String> {
    let mut refused = Vec::new();
    for dir in dirs {
        match link_in(target, dir) {
            Ok(link) => {
                let on_path = path
                    .is_some_and(|path| std::env::split_paths(path).any(|searched| searched == *dir));
                return Ok(Linked { link, on_path });
            }
            Err(why) => refused.push(why),
        }
    }
    if refused.is_empty() {
        return Err("no folder to link into".to_owned());
    }
    Err(refused.join("; "))
}

fn link_in(target: &Path, dir: &Path) -> Result<PathBuf, String> {
    let link = dir.join("mk");
    let fail = |what: &str, error: io::Error| format!("{what} {}: {error}", dir.display());
    std::fs::create_dir_all(dir).map_err(|error| fail("cannot create", error))?;
    match std::fs::symlink_metadata(&link) {
        Ok(meta) if meta.file_type().is_symlink() => {
            // An earlier install (or a stale one of an older bundle) is replaced; a link to
            // something that is not an `mk` is somebody else's.
            let ours = std::fs::read_link(&link)
                .is_ok_and(|to| to.file_name() == Some(OsStr::new("mk")));
            if !ours {
                return Err(format!("{} links elsewhere", link.display()));
            }
            std::fs::remove_file(&link).map_err(|error| fail("cannot replace the link in", error))?;
        }
        Ok(_) => return Err(format!("{} exists and is not a link", link.display())),
        Err(error) if error.kind() == io::ErrorKind::NotFound => {}
        Err(error) => return Err(fail("cannot look in", error)),
    }
    symlink(target, &link).map_err(|error| fail("cannot link in", error))?;
    Ok(link)
}

#[cfg(unix)]
fn symlink(target: &Path, link: &Path) -> io::Result<()> {
    std::os::unix::fs::symlink(target, link)
}

#[cfg(not(unix))]
fn symlink(_target: &Path, _link: &Path) -> io::Result<()> {
    Err(io::ErrorKind::Unsupported.into())
}
```

```rust
/// `base` plus the platform's executable suffix, next to the running executable when it is a
/// file there, else the bare name for `PATH` to find. The daemon also finds `mk` this way.
/// Next to the real file of the executable, so an `mk` reached through a link (the macOS
/// "Install mk command") still finds the daemon in its bundle.
pub fn sibling_exe(base: &str) -> anyhow::Result<PathBuf> {
    let name = format!("{base}{}", std::env::consts::EXE_SUFFIX);
    let exe = std::env::current_exe().context("locate the running executable")?;
    Ok(sibling_of(&exe, &name))
}

fn sibling_of(exe: &std::path::Path, name: &str) -> PathBuf {
    // Windows' `canonicalize` gives `\\?\` paths that `cmd.exe` and friends dislike; its
    // `current_exe` is already the real file.
    let exe = if cfg!(unix) {
        std::fs::canonicalize(exe).unwrap_or_else(|_| exe.to_path_buf())
    } else {
        exe.to_path_buf()
    };
    let sibling = exe.with_file_name(name);
    if sibling.is_file() {
        sibling
    } else {
        PathBuf::from(name)
    }
}
```

## Not fixed (and why)

|Item|Reason|
|---|---|
|Dock → Quit and log-out ask nothing; unsaved Files edits are lost on those two paths|gpui 0.3.7 cannot veto them (`on_app_quit` runs after the decision, 200 ms). A veto needs `applicationShouldTerminate:` added to gpui's private delegate, an `unsafe` runtime call the workspace denies. Window places are saved and machine windows asked to quit (Task 7). Revisit when gpui exposes the hook.|
|Edit menu has no Cut, Select All, Undo and does not reach the Files editor or text fields|They take key events, not actions; no action exists to dispatch (the keys work). Only the terminal's `Copy` and `Paste` commands are actions.|
|Single instance on macOS|LaunchServices already reuses a running bundle for Finder, Dock and `open`; a terminal launch of the binary shares the daemon (harmless, as on Linux). The toast link and launcher raise are Windows-only. Decided in ADR 0100.|
|Raising a running machine window from "Machine: Open" on macOS|It is a separate process; macOS 14 limits one app activating another [INFERENCE]. Its Dock icon and Cmd+Tab reach it.|
|`mkrew --machine` children keep their own Dock icon|Each machine window is its own process (ADR 0089); an accessory policy would remove its menu bar and Cmd+Tab entry. Decided in ADR 0100, one HUMAN_CHECKS look.|
|Dock menu (`set_dock_menu`) with the Inbox and machine list|Not requested; the badge, bounce and app menu cover attention.|
|A window list in the Window menu|gpui has no `setWindowsMenu` [INFERENCE]; Minimize and Zoom only.|
|Windows-only profiles (`cmd`, `powershell`, `git-bash`) still seeded into the config folder|They are compiled into the daemon (`SAMPLE_PROFILES`); only the bundle's reference copy is filtered (as asked). The New menu already hides profiles whose program is not installed.|
|`git`, `ssh` and `tailscale` subprocesses of the daemon use the bare Finder `PATH`|Only agents, the default shell and program lookups were reported; `/usr/bin/git` exists on every Mac. Add `login_path::path()` to them if a tool in `/opt/homebrew/bin` is needed.|
|Setting titles "Close to tray" and "Flash the taskbar"|`mkrew-core` has no OS enum; their help lines name macOS (Tasks 6 and 8), the titles stay.|
|Notarization on the user's behalf|Needs the six Apple secrets (Task 10 lists them); implemented and gated on them, ad-hoc signing otherwise.|
|Intel Macs|No asset is built (existing behavior, `update.rs` sends them to the release page).|
